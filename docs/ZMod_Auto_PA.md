# Экспериментальная Auto PA AD5M / AD5M Pro

Не включена по умолчанию. Проверена на одном AD5M, AD5M Pro требует проверки.
Нужны совместимые прошивка MCU и Klipper из экспериментальных PR, отключённый родной экран, штатный UART 40000. NumPy уже используется калибровкой шейперов AD5M; дополнительные SciPy/Pandas не нужны.

В тестовой конфигурации подключить `config/zmod-pa.cfg` (указать model: AD5M Pro для Pro). Если секция [zmod_pa] уже существует, не дублировать её; добавить только макросы. Очистить стол и зону продувки. Калибровка не выполняется во время печати/паузы.

1. Полностью выгрузить филамент, включая остатки из экструдера. Выполнить `TEST_PA_EMPTY CONFIRM=1` (по умолчанию 210 °C). Две пустые записи сохраняются атомарно. При изменении настроек драйвера, механики или повторной сборке экструдера калибровать заново.
2. Загрузить и продуть филамент. Установить рабочую температуру или указать `TEMP` (например `TEST_PA TEMP=250` для подходящего PETG). 
3. `TEST_PA T=0 PA_MIN=0.01 PA_MAX=0.10 PA_COUNT=3`. Параметры совместимы с C5 по имени; пределы ограничивают результат, не меняют последовательность измерений. При PA_COUNT менее 3 результат диагностический, не считается достоверным.
4. Результат не применяется автоматически. Прислать `mod_data/auto_pa/YYYYMMDD_HHMMSS_pa.zip` и PA из печатного теста OrcaSlicer при той же температуре. Версия Z-Mod берётся из /tmp/version.txt, если доступна; иначе указать её вручную. Архив содержит только базу, записи и результат, не общий конфиг.

Автоматически проверяются отсутствие печати, прошивка MCU, безопасная парковка по _CLIENT_VARIABLE, homing, Z>=50, моторы, прогрев, ток, PA smooth_time и состояние датчиков. После теста восстанавливаются датчики, ток, целевая температура, PA и G-code состояние. Головка остаётся в точке парковки, оси остаются включены. Не оставлять принтер без присмотра; при пропусках шагов остановить тест. При shutdown нужна штатная процедура восстановления принтера.

Алгоритм sg250-v1: 250 Гц, FAST=8, ACCEL=1000, smooth_time=.04, ток .6/.6 A, PA 0/.02/.04/.06/.08, фильтр 20 мс, производные позиции E по 3 точкам (полином 2), окно разгона ±80 мс, tau .005–.150, экспериментальный коэффициент 1.7. Порог gain 1%, проверки leave-one-pass-out и независимых пустых баз, разброс <=.03; коэффициент пока не подтверждён на широкой выборке. Активная обработанная база `mod_data/auto_pa/empty.zip` содержит только две пустые кривые (время, SG, границы разгона), настройки и результат проверки базы. Она читается без разбора исходных CSV. Каждый запуск сохраняется в отдельный архив `YYYYMMDD_HHMMSS_empty.zip` или `YYYYMMDD_HHMMSS_pa.zip`: исходные CSV, обработанная база и `result.json`. Предыдущие архивы не удаляются; активная база заменяется только после проверки. При ошибке записанные данные тоже архивируются; если архивация не удалась, рабочий каталог остаётся. Диагностические команды по умолчанию создают архивы с суффиксом `sg` или `test_pa`. При совпадении времени добавляется числовой суффикс. Старую базу с CSV необходимо переснять. Никакого вычисления в MCU.
